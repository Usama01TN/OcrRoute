# Decisions

| # | Decision | Rationale |
|---|---|---|
| 1 | **Sync SQLAlchemy in a thread pool** instead of async `aiosqlite`. | Every engine is blocking anyway; a single sync session model with `anyio.to_thread` is simpler, and SQLite gains nothing from async. Deviation from the original spec wording, same behaviour. |
| 2 | **Server-rendered Jinja2 + HTMX/vanilla JS + vendored Chart.js** for the panel; Vite/React SPA rejected. | Ships inside the wheel, zero Node runtime, fully offline, one mental model with the desktop app (both are thin clients of `/v1`). Tailwind CLI was also dropped: a 200-line hand-written stylesheet avoids a build step. |
| 3 | **Panel JS calls `/v1` with the session cookie** (CSRF guard = `X-Requested-With` header + SameSite=Strict) rather than duplicating CRUD in panel routes. | One implementation of every mutation; audit log and validation live in one place. |
| 4 | **Alembic `0001_initial` uses `Base.metadata.create_all`**; `init_db()` also calls `create_all` at startup. | Zero-config first run; later schema changes are proper Alembic revisions. |
| 5 | **Engine demotion at runtime** (`engine_missing` → unavailable). | Many local engines import fine but fail on first use when torch/onnxruntime is absent; without demotion `auto` would keep paying for failures. |
| 6 | **Hand-written searchable PDF and .docx writers** (no reportlab / python-docx). | Keeps the core install light; text layer uses Helvetica/WinAnsi, so non-Latin scripts are not selectable in PDFs (documented limitation). |
| 7 | **Panel probe/test/verify runs are tagged `origin=panel_test`** and excluded from KPIs. | Operator diagnostics must not skew usage or cost. |
| 8 | Open question 1 (tenancy): **API keys only** for v0.1. | Per-key isolation covers the single-operator case; a `tenants` table can be added without touching runs. |
| 9 | Open question 2 (panel auth): **local users only**; trusted-header/OIDC deferred. | Keep the first release small; the session middleware is the single place to extend. |
| 10 | Open question 3 (model weights): **pre-fetch by the operator**; on-demand download deferred. | Downloading multi-GB weights from a web UI needs disk/consent UX that is out of scope for 0.1; the Engines page shows the install hint instead. |
| 11 | Open question 4 (queue): **in-process `ThreadPoolExecutor`** persisted to SQLite; upload payloads for batch items are held in memory. | Single-node target. Documented: uploads lost on restart are reported per item. |
| 12 | Open question 5 (cost data): **bundled starter prices in `engines.toml`, editable in the panel**, labelled "estimates". | Operators must be able to correct vendor pricing without a code change. |
| 13 | **No overlap with other gateways**: `ocrroute` namespace, port 20256 (20128 refused at startup and in `doctor`), no chat/completions or agent-protocol endpoints, own vocabulary (Route/Attempt/Engine), no reused assets/text. | Hard requirement from the brief. |
| 14 | **AioOCR is imported as given, never vendored or edited**; `ocrroute/enginelib.py` reproduces the run-from-its-own-folder import environment the library expects. | The brief requires importing the same library; the bridge keeps its discovery and `OcrBase` working without touching it. |
| 15 | **Gateway code follows AioOCR's style** (Python-2-compatible look: `(object)`, `super(Cls, self)`, `__m_` + getX/setX, `.format()`, no dataclasses/hints). Annotations kept only where SQLAlchemy `Mapped`, Pydantic, FastAPI and Typer require them at runtime; snake_case `property()` aliases expose the private fields. | Same-style requirement from the brief, balanced against frameworks that read annotations at runtime. |
| 16 | **Providers are auto-seeded for every available engine**; cloud ones simply wait for a credential. | "Detect and import all OCR providers automatically": zero clicks from detection to a usable route member. |
| 17 | **Hot rediscovery reuses `AioOCR._discoverOcrPlugins()`** rather than re-implementing discovery; a snapshot of engine-module mtimes decides when to rescan. | Keeps the library the single source of truth for which engines exist. |
| 18 | **Python 2/3 syntax compatibility is best-effort by construction**: FastAPI, SQLAlchemy 2 and PyQt5 wheels only exist for Python 3, so the gateway cannot *run* on 2.7; the code nevertheless keeps 2/3-portable idioms (`__future__`, `py23` shims, `.format`, no kw-only args, no `raise from`). `async def` handlers (15) and framework-read annotations are the listed exceptions. | Honest about what "supports Python 2 and 3" can mean for this stack. |
| 19 | **One JSON vocabulary for both UIs** instead of gettext `.po` + Qt `.ts/.qm`. | No `lrelease`/`msgfmt` toolchain, one file per language, contributors edit plain JSON, tests enforce completeness. |
| 20 | **Bootstrap 5 (vendored) instead of ReactBits/React** for the panel. | ReactBits needs a React/Vite build chain and CDN-free bundling; Bootstrap ships as two static files, keeps the panel dependency-free and offline, and gives responsive layout, offcanvas navigation and dark mode out of the box. |
| 21 | **PyInstaller `--onedir` by default, `--onefile` optional.** | One-dir starts faster and is friendlier to antivirus heuristics; one-file is available for portable use. |
| 22 | **Tunnels run as child processes of the gateway** (cloudflared / tailscale / ngrok binaries on PATH); "Install & enable" shows the exact platform command and runs it only when the operator confirms. | Keeps secrets and network exposure explicit; no bundled third-party binaries; works identically on the three OSes. |
| 23 | **"Cloud OmniRoute" has no equivalent**; the slot is a manually configured Public URL (reverse proxy). | Non-overlap rule: OcrRoute does not attach to another gateway's cloud. The `OmniRouteOcr` plugin shipped in the given library is discovered like any engine. |
| 24 | **No em dash anywhere in project sources** (test-enforced); the given AioOCR files are left untouched. | Explicit request. |
| 25 | **Design tokens taken from the fork's `app.css`** (colours, sidebar treatment, radii, typography); its markup and Alpine-based shell were not adopted because this project's Bootstrap shell already implements the requested console organisation and carries the feature set. | Applies the requested look without regressing features. |
| 26 | **Lifecycle through `server.should_exit` rather than signals**; unknown mode never terminates the host process. | Works identically on Windows/macOS/Linux and inside the desktop's embedded server; a stray shutdown request can no longer kill a host such as pytest or the desktop app. |
| 27 | **Tunnel binaries installed per user into `~/.ocrroute/bin`**; only Tailscale uses a system installer. | One click without administrator rights; the gateway process can always find and start what it installed. |
| 28 | **Auto routes exclude cloud providers without credentials and try lightweight engines first** while health is unknown. | Seeding a provider for every engine is convenient, but a route must never spend attempts on engines that cannot possibly succeed. |
