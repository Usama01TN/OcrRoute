# Internationalisation

Both UIs share one vocabulary: the JSON catalogues in `ocrroute/i18n/` (`en.json` is the source language;
`fr`, `es`, `de`, `ar` ship complete). `ar` (and any code listed in `i18n.RTL`) switches to right-to-left layout
in the web panel (`dir="rtl"`, logical CSS properties) and the desktop (`QApplication.setLayoutDirection`).

| Where | Mechanism | How the language is chosen |
|---|---|---|
| Web panel | Jinja global `_()` → `i18n.translate`; `rel()` for humanised times | cookie `ocrroute_lang` (set via the sidebar selector / `/panel/lang/<code>`) → `?lang=` → `Accept-Language` → `OCRROUTE_DEFAULT_LANGUAGE` |
| Desktop | `ocrroute.desktop.i18n.JsonTranslator` (a `QTranslator` over the same JSON), so every `self.tr()` resolves through it; changing the language in *Settings* rebuilds the window live | `QSettings ui/language` → OS locale → English |
| CLI / API | English (machine-facing) | - |

## Adding a language

1. Copy `ocrroute/i18n/en.json` to `<code>.json` and translate the values (keys stay English).
2. Add the native name to `i18n.NAMES`; add the code to `i18n.RTL` if it is right-to-left.
3. Run `pytest tests/unit/test_i18n_py23_detection.py` - it fails if any key is missing.

## Adding a string

Use `{{ _('Your text') }}` in templates or `self.tr('Your text')` in the desktop, then add the key to **every**
catalogue. Placeholders use `{name}` and are filled with keyword arguments: `_('Welcome back, {name}.', name=user)`.
